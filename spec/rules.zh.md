# 出卡规矩

交给 AI 出卡时共用的话。原文取自 ChatCards 的出卡提示词（`CardMaker.systemPrompt`），一字不差。

`## 卡片的写法` 和 `## 输出格式` 两节会生成进两个包（`cardRules`、`outputFormat`、`rulesPrompt`），改这两节就是改规范：每一条是一行 `- ` 开头的原文，代码块里是输出格式。别的节只是说明，不进包。

## 卡片的写法

- 一张卡只问一个点。问题要离开材料也能看懂：写出具体的工具、语言、场景的名字，不写「这个项目」「上面那个」。
- 答案尽量短：一句话或一条命令，最好不超过 40 个字；要展开的放进 more：最多 3 条，一行一条，每条一句。
- quote：从材料里原样摘一句支撑这张卡的话，不超过 80 个字，方便回去找出处。
- tags：这张卡的主题，只写一个，用大家都懂的通用名字（Git、macOS、SwiftUI、Python、德国交规），同一份材料里同类的卡用同一个主题。
- 用材料的语言写（材料主要是中文就写中文；命令、代码、专有名词保留原文）。
- 宁缺毋滥：没有值得记的就返回空数组。

## 输出格式

```json
{"cards":[{"q":"问题","a":"答案","more":"补充说明，一行一条，没有就空字符串","quote":"原文摘句","tags":["主题"]}]}
```

## 怎么拼进提示词

`rulesPrompt` 是下面这一段，接在各软件自己的开场白和「挑什么做成卡」后面：

```text
卡片的写法：
- （上面六条，一条一行）

只输出 JSON，格式：
（输出格式那一行）
```

ChatCards 现在的提示词就是「开场白 + 值得做成卡片的 + 不要做成卡片的 + rulesPrompt」。

## 不在这里的

- 开场白和「挑什么做成卡」（值得做成卡片的、不要做成卡片的）讲的是各软件自己的材料（会话、文档、PDF、截图），留在各软件里。
- 一问做一张的软件（画布笔记）不用「tags」「宁缺毋滥」两条，输出也是一行一张、带 `id`；这些在各软件里自己写，其余四条照抄这里。
- 用哪家 AI、Key 存在哪，各软件自己管。这个仓库不调 AI、不存 Key。
